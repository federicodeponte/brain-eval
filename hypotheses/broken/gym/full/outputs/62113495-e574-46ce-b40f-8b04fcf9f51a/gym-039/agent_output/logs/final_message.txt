**What I found about data issues**
- `orientation_deg` is perfectly deterministic from `y` in both labeled splits (same mapping every trial), so it is label-derived metadata and would be leakage if used as a feature.
- It is also absent in test, so any model relying on it would not transfer.
- Minor naming inconsistency: field name `orientation_deg` while classes are described as motion direction labels.
